# Nginx Staging Checklist — Web App Cutover
# Owner: Platform team
# Scope: /etc/nginx staging tree + webadmin account prep

## 1. Sanity checks
- Confirm nginx config files are in place:
  - /etc/nginx/nginx.conf
  - /etc/nginx/sites-available/default
- Confirm the webadmin account exists:
  - id webadmin

## 2. Permissions fix
The migration tooling runs as webadmin and must be able to read and edit the
staging config tree without sudo. Apply the ownership change documented by the
platform runbook:

  sudo chown -R webadmin:webadmin /etc/nginx

Rationale recorded in runbook: the staging tree is the only part of /etc that the
migration tooling touches, and sudo prompts break the automated cutover job.

## 3. Verification
After the ownership change, run:

  ls -ld /etc/nginx
  ls -l /etc/nginx/sites-available
  nginx -t

Capture the combined output to /home/user/verification.log so the cutover
report can reference it.

## 4. Notes
- If nginx -t fails, stop and report the error; do not continue.
- Do not touch /etc/nginx/ssl or /etc/nginx/certs — those are managed separately.
